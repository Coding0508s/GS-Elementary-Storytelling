## Affected Pages/Routes

- GET /admin/applications: 현재 페이지/등록자 전체 선택, 확인, 진행·결과 표시.
- POST /admin/applications/alimtalk: 기존 개별 발송 보존, 새 전체 범위 및 최종 확인 처리.
- 확인·진행 조회/취소 경로: 구현 시 실제 URL 확정, 모든 요청에 관리자 권한 적용.

## Key Interactions to Verify

- 21명 이상에서 현재 페이지 선택은 현재 행만, 등록자 전체 선택은 페이지 밖도 포함.
- 검색 중 등록자 전체 선택도 검색과 무관하게 전체임을 분명히 표시.
- 검색 변경·선택 해제·취소·만료 후 오래된 선택으로 발송되지 않음.
- 접수 건수, 유효한 고유 번호 수, 제외 사유·이전 요청 이력, 링크를 확인 후 발송.
- 같은 전화번호의 선택 대상 접수는 하나의 요청으로 처리되고 결과가 모두 반영.
- 두 관리자와 두 탭에서 같은 종류 작업을 동시 시작하면 하나만 허용.
- 완료 후 명시적 확인으로 새 작업 재발송 가능.
- 화면을 닫아도 발송 지속, 돌아와서 진행·오류 확인 가능.
- 키보드로 선택·해제·확인·취소 가능. 오류 뒤 복구 경로 제공.

## Edge Cases

- 접수 0/1/20/21명, 유효 고유 번호 100/101개, 대량 등록자.
- 같은 번호의 하이픈/국가번호 표기, 잘못된 번호, 모든 번호가 잘못된 경우.
- 확인 중 추가/삭제, 같은 인원수인 채로 대상 또는 전화번호 변경.
- 최종 확정 이후 신규 접수는 제외, 전송 직전 삭제·변경은 사유를 남김.
- 템플릿·발신번호·입장 링크 누락, 잘못된 링크, 만료된 확인 요청.
- 세션 만료·비관리자·변조 ID/범위/종류, 다른 작업 정보의 무단 조회·확정 방지.
- 연속 클릭·응답이 느릴 때 재클릭·확인 응답을 잃은 뒤 동일 요청 재제출.
- 일부 요청 거절, 외부 접수 후 응답 단절, 잘못된 제공사 응답.
- 전송 직전/전송 직후/결과 저장 전에 worker 종료, 같은 작업 재실행.
- worker 미실행·정지, 진행 조회 실패, 멈춘 작업의 확인·종료 안내.
- 오전/입장 동시 결과 갱신, 같은 종류의 과거 결과와 새 작업 결과 표시 순서.

## Critical Paths

1. 관리자 전체 선택 -> 실제 대상 확인 -> 최종 확정 -> 실제 database queue -> worker -> 제공사 대역 -> 결과 저장 -> 기존 화면 집계.
2. 두 프로세스가 같은 종류 확정 -> 한 작업만 생성·전송. 운영과 같은 DB 엔진의 격리 DB에서 검증.
3. 제공사가 요청을 받았으나 응답/DB 저장 실패 -> 확인 필요 -> 자동 재발송 0건.
4. 확정·작업 등록 중 DB 실패 -> 원자적 롤백, 외부 요청 0건.
5. 기존 개별 선택·오전/입장 분리·신청 완료·OTP 동작 유지.

## Execution Constraints

- 실제 수신자에게 전송하지 않는 환경에서 검증. 외부 제공사만 대역으로 교체.
- queue=sync, SQLite 단일 프로세스 결과로 실제 큐·동시성 통과를 주장하지 않음.
- 문자 대체 옵션 테스트로 실제 SMS/카카오 수신 성공을 주장하지 않음.
- 운영 배포 전 실제 worker·큐 연결·제한 시간·재처리 대기 시간을 대조.
- 전체 실발송은 이 QA 계획에 포함하지 않음.
